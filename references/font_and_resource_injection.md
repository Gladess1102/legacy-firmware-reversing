# 资源树解析与全量中文字库注入方法论 (Font & Resource Injection)

在嵌入式固件汉化与界面定制中，常见难题是**厂商使用私有资源树格式、字体索引非标准编码、且 Flash 分区尺寸受到严格物理限制（无法扩容）**。本指南总结了从私有资源逆向、字模映射破解、全量 GB2312 汉字零膨胀注入到像素级 UI 瑕疵修复的完整方法论。

---

## 1. 私有二进制资源树逆向 (Resource Tree Disassembly)

老式嵌入式系统（如 SigmaTel STMP 平台）通常将字符串、字模、位图以统一的描述符打包在专用分区（如 Target 08）。

### 1.1 描述符结构特征（以 24-bit 架构为例）
资源文件通常由连续的“描述符头 + 载荷数据”构成：
- **标准 9 字节头**：
  - `ID`: 24-bit LE (3 字节)
  - `Length`: 24-bit LE (3 字节，载荷字节数)
  - `Type`: 24-bit LE (3 字节)
    - `0x000001`: 文本字符串 (String)
    - `0x000002`: 二进制数据/配置表 (Raw Data)
    - `0x000003`: 单色位图/字模 (Bitmap/Glyph)
    - `0x000004`: 界面按钮/交互组件 (Button)
- **变体结构识别**：部分固件在扇区重排或编译器优化时会插入填充标记（例如 `ID(3) + Length(3) + 0xDEDE(2) + Type(3)`），在遍历时必须根据签名动态对齐。

## 2. 字模解码与“映射悖论”破解 (The Mapping Paradox)

### 2.1 字模物理排布（以 12x8 点阵为例）
字模位图载荷通常包含：
- **元数据**：宽度 `Width` (3B LE, 如 8)、高度 `Height` (3B LE, 如 12)。
- **像素点阵**：12 行 $\times$ 8 列 = 12 字节。每字节代表一行，MSB（最高位）在最左端（`1` 为亮，`0` 为暗）。
- **度量属性（Metrics）**：载荷尾部通常附带字间距、基线偏移等附加字节，必须严格保留。

### 2.2 破解字符映射悖论
当尝试建立 `编码 -> 字模` 对应关系时，初学者往往陷入死循环：
- 假设 1：按 ASCII / JIS 编码顺序？$\to$ 证伪。
- 假设 2：按 Shift-JIS 区位码顺序？$\to$ 证伪。
- 假设 3：按 Unicode 码点顺序？$\to$ 证伪。

**破局方法论：锚点视觉识别 + 频度逆映射**
1. **全量位图批量转图**：
   编写脚本将所有 Type 3 资源提取，按位图格式逐一渲染为 PNG（如生成 7000+ 个字模小图）。
2. **寻找基准锚点（Anchor Glyphs）**：
   在图集中用肉眼或脚本模板匹配数字 `0-9`、英文字母 `A-Z`、标点符号及常见高频假名。
3. **推导内部 Glyph ID (GID) 编址规律**：
   嵌入式系统多使用内部连续 GID（从 0 或 1 起递增），UI 字符串存储的不是 ASCII/SJIS 码，而是私有的 16 位或 24 位 GID 序列。
4. **建立字库字典字典库**：
   通过锚点反推字符串表中的文本，确立 `字符 <-> GID <-> Resource ID` 的三元映射表（如 `gb2312_full_map.json`）。

## 3. 全量 GB2312 汉字零膨胀注入法 (Zero-Footprint Injection)

### 3.1 核心约束
- Flash 分区页数与扇区总数固定（例如 896 页），**绝对不能扩容**。
- 原生固件仅包含日文汉字（约 2000~3000 个），而国标 GB2312 需要 6,763 个汉字。

### 3.2 槽位置换与空间复用策略
1. **盘点可用字模槽位**：
   - 原厂字库中包含大量日文罕见字、扩展符号和未使用的预留槽位（Slot）。
   - 提取所有可用字模槽位的 Resource ID 列表。
2. **现代字模栅格化流水线**：
   - 选用符合尺寸的优秀开源点阵字库（如文泉驿点阵黑体、SimSun 12px）。
   - 使用 Python FreeType / PIL 将 6,763 个汉字逐一渲染为严格匹配硬件规格的点阵矩阵（例如 $12 \times 8$ 或 $16 \times 16$）。
3. **原位二进制注入（In-place Patching）**：
   - 保持字模的描述符头（ID、Length、Type）和尾部度量属性完全不变。
   - 仅覆盖中部的像素字节数组。
   - 保持固件整个镜像总长度、扇区边界、物理页尾对齐 100% 不变。

## 4. 像素级 UI 瑕疵修复 (Pixel Mask Patching)

汉化后常伴随界面显示瑕疵（如原厂为日文字符设计的固定边框、竖线掩码遮挡了中文字符）。

### 4.1 识别静态背景图与动态文本
- 很多设备界面上的方括号 `[`、分隔竖线 `|`、单位标签并非由代码绘制，而是直接烙印在背景位图（如 CID 1293~1297）中。
- 当动态文本内容变宽（如频率显示由 `89.9` 变为 `104.5`）时，就会与背景图上的固定线条产生视觉重叠，形成难以消除的“鬼影”。

### 4.2 位图掩码手术
1. 定位受影响的背景位图 Resource ID。
2. 将位图转为灰度矩阵，定位冲突区域的坐标窗口（例如 $X=30..127, Y=0..14$）。
3. 在脚本中对该区域的对应 bit 执行位清除（Bit-clear / `0x00` 填充）。
4. 重新打包回固件，实现干净无遮挡的纯净 OLED/LCD 显示界面。
