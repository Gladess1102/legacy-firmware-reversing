# 多 Agent 协同逆向攻坚协议 (Multi-Agent Reverse Engineering Protocol)

在面对周期长、复杂度高、涉及物理硬件且有多位 AI Agent（或人机交替多会话）参与的逆向破解任务时，最容易出现效率陷阱：**假说失忆（重复尝试已失败方案）、目标漂移（频繁更换主线目标）、改动互踩（后一个版本意外冲掉前一个版本的成果）**。

本指南提炼了一套经过实战检验的多 Agent 协同工程规范（以 `PROJECT-STATE.md` 为核心）。

---

## 1. 协同死穴与防范对策

| 经典病灶 | 典型症状 | 根治对策 |
|---|---|---|
| **假说失忆** | Agent A 验证过某方案失败，两轮后 Agent B 换个名字重做一遍 | 建立**【已否证清单】**，注明失败现象与物理真因 |
| **改动互踩** | 新版本调好了收音机，却不小心把上一轮修好的字模或 UI 竖线改回去了 | 确立**【累加式基线（Baseline Chain）】**，每个新版本必须派生自已知最佳版本 |
| **伪突破误导** | 某个单边参数改动造成虚假表象（如断崖数字移动），被误当成突破全盘采纳 | 实行**【双 Agent 交叉复核】**，强行审查数学与物理不变量 |
| **单次实验成本过高** | 每次实验都需要人工刷机、断电、看屏幕，导致人肉测试成为瓶颈 | 推动**【PC 端仿真先行】**，90% 逻辑在仿真器中跑通后再上真机 |

---

## 2. 状态基石：`PROJECT-STATE.md` 规范

所有参与项目的 Agent 必须在工作目录维护一份唯一的全局状态文件 `PROJECT-STATE.md`，并在接手与交接时强制阅读和增量更新。

### 2.1 标准文档大纲
1. **设备硬件与芯片架构确证信息**（主控、DSP 核、外设型号、存储介质）。
2. **用户真实目标优先级**（明确底线：例如 1. 不变砖，2. 中文化，3. 调谐扩展）。
3. **已确证事实清单（Ground Truths）**：
   - 记录已有真机测试或硬件证据支撑的事实（例如：SCSI 读写帧结构、物理扇区尺寸、字模点阵规格）。**严禁重复求证已确证事实**。
4. **已彻底否证清单（Disproven Hypotheses）**：
   - 记录每一条被证伪的技术路径、实验版本及不可行的深层根因。
5. **累加实验矩阵表（Experiment Matrix）**：
   ```markdown
   | 版本 | 基于基线 | 改动内容 | 观测现象 | 结论与归因 |
   |---|---|---|---|---|
   | v24 | v23 | 恢复 K=100，修补背景位图遮罩 | 界面干净，89.8 清晰，90 断崖 | 最佳稳定版，UI 完成 |
   | v25 | v24 | NOP 5 处校验跳转 | 白屏死循环 | 证伪：do a0 计数下溢 |
   | v32 | v24 | CAP 斜率 ×3 -> ×1 | 全频段无响应 | 证伪：射频前端不可控 |
   ```
6. **黄金基线与一键回滚指令**：
   - 永远明确指明当前公认的最优、最安全固件文件路径与一键刷写命令。

## 3. 跨 Agent 补丁生成与验证铁律

### 3.1 补丁生成三原则
1. **不动页尾与保留区**：
   - 严格保护 Flash 物理扇区尾标（除非有百分之百证据证明其为垃圾数据），禁止盲目使用全局常量覆盖物理页尾。
2. **最小变量原则**：
   - 一次只改一个独立假设对应的字节。例如：改跳转就绝不同时改常量；改除数就必须且仅对称改动乘数。
3. **自包含与无损输出**：
   - 输出镜像必须严格进行 MD5 校验和长度校验，禁止生成任何尺寸畸变的中间文件。

### 3.2 离线证伪先于真机实测
- 当提出一个新解释（如“越界是因为数组只有 70 项”）时，**首先在 PC 端仿真器（如 JIT / Trace 工具）中跑输入对比**。
- 只有在仿真器中观察到状态变量行为与推论一致、且未触发非法指令异常后，才向用户交付刷机包。这可将真机死机、白屏的事故率降低 90% 以上。
