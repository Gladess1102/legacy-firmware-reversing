# 假说证伪与软硬件边界判定方法论 (Hypothesis Testing & Hardware Limits)

在逆向工程中，当设备出现功能截止（如“收音机跨过 90.0MHz 声音断崖式下跌”、“某些高采样率音频无法播放”、“某个波特率通信失步”）时，工程师最容易陷入的无底洞是：**误将物理硬件的客观极限当成软件缺陷，在固件中无休止地尝试死循环补丁**；或者**在软件修改中踩入硬件指令集暗坑导致机器白屏假死**。本指南总结了严密的单变量证伪流水线、DSP 硬件循环暗坑防范与软硬件物理边界的判定准则。

---

## 1. 严格的单变量证伪准则 (The Single-Variable Rule)

逆向打补丁切忌“毕其功于一役”。一次同时修改多个跳转、常量或结构，会导致实验结果彻底失去可解释性。

### 1.1 对偶对称修改原则（Dual Invariant Symmetry）
在很多信号处理流水线中，存在成对出现的互逆函数（如编码与解码、标定与反标定）：
- 示例：`CounterToFreq`（硬件回读计数转显示频率：$f = 76000 + c \times K/2$）与 `FreqToCounter`（目标频率转硬件计数：$c = (f - 76000) / (K/2)$）。
- **致命失误**：只修改了前者的乘数 $K$（由 100 改为 200），未同步修改后者的除数。
  - **后果**：调谐目标被按 $K=100$ 发给硬件，回读时却被按 $K=200$ 还原为假频率。由于回读公式不对称，软件误以为断崖被“推迟”到了 104MHz，实则是回读刻度被成倍拉伸造成的虚假错觉，伴随的是全频段台位错乱与搜台死循环。
- **铁律**：凡涉及互逆映射系统，改动必须严格成对同步验证，否则任何“表象位移”都不可作为推断依据。

## 2. DSP 硬件循环暗坑（The `do a0` Trap）

在 x86 或 ARM 架构上，将条件跳转指令（如 `jle`）替换为 `NOP` 通常意味着直通执行后续代码。但在具备硬件循环（Hardware Loop）特性的架构（如 Motorola DSP56k）上，这种操作极其致命。

### 2.1 硬件循环计数器溢出机制
考虑以下经典的反汇编片段：
```asm
sub   y1, b                 ; 计算步长差值: delta = target - current
jle   $fail_handler         ; 保护跳转：如果 delta <= 0 则退出，防止非法步长
move  b, a
do    a0, $loop_end         ; 硬件循环指令：循环执行 a0 次
; ... 循环体 ...
$loop_end:
```

### 2.2 为什么 NOP 会导致白屏/卡死？
- 当外部输入超限导致 `delta <= 0` 时，若强行将 `jle $fail_handler` 改为 `NOP`：
- CPU 将带着 $a_0 \le 0$（例如 $0$ 或负数补码）直接穿透进入 `do a0` 指令！
- 在 DSP56k 硬件执行单元中，硬件循环计数器（LC）从 0 开始递减，直接下溢为 $0xFFFFFF$（即 $2^{24} = 16,777,216$ 次循环）！
- 一个原本仅需几十个周期的函数瞬间被锁定在千万级硬件循环中，主事件循环被彻底饿死，屏幕甚至来不及点亮初始化即表现为**白屏死机**。

### 2.3 防范铁律
1. 绝对不要在未搞清下文寄存器用途的情况下，盲目 NOP 条件跳转。
2. 若需绕过失败分支，应改写为**赋予安全合法默认值**（如 `move #1, b` + `NOP`），确保后续硬件计数器绝对为正。

## 3. 软硬件物理边界的四步判定法 (Hardware vs Software Proof)

当一个参数在某一数值发生阶跃式失效（如 90.0MHz 信号跌入噪声底）时，如何确证这是“硬件物料极限”还是“固件代码逻辑”？必须完成以下四步闭环推演：

```
[步骤 1: 软件闸门放开]
       │  (放开上限分支/常量钳位)
       ▼
   调谐动作执行但信号依旧极弱/沙沙声？ ───► YES
       │
[步骤 2: 射频谐振参数扰动]
       │  (大幅改变 CAP 斜率 / 变容管控制字)
       ▼
   全频段无任何可观测的声学/频谱响应？ ───► YES
       │
[步骤 3: 硬件时间基准常数证伪]
       │  (强行改动换算比例 K 压缩档位)
       ▼
   全频段失配，原正常频点亦全部错乱？ ───► YES
       │
[步骤 4: 物理拓扑与器件规格求证]
       │  (查阅器件手册与 LC 谐振公式)
       ▼
   芯片家族支持宽频，但 PCB 外部 LC 槽
   与变容二极管为本土市场专门定制？ ───► YES
       │
       ▼
【定论：属于物理硬件边界，软件已达极限】
```

### 3.1 步骤详解与实战依据
1. **步骤 1：软件闸门完全放开**
   - 将所有可查证的频率边界判断（如 90000 比较值、档位 70 限制）解除。如果设备调谐状态机已经发出写指令，但接收到的依然是纯白噪且底噪电平未变，说明物理本振（VCO）未能在目标频段建立有效谐振。
2. **步骤 2：射频谐振参数扰动实验**
   - 寻找控制前端 LC 调谐电容（如 `FM_CAP`）的寄存器写逻辑，故意将其系数缩放（例如缩小到 1/3）。
   - 如果无论怎样修改，超限频段完全没有任何音频变化，说明内部开关电容阵列即使调到极限，由于外部并联固定电感 $L$ 过大，根据 LC 谐振公式 $f = \frac{1}{2\pi \sqrt{LC}}$，物理谐振频率根本无法上升到 90MHz 以上。
3. **步骤 3：硬件时间基准常数证伪**
   - 测量硬件计数器回读值 $c$ 与频率的关系：$c = (f - f_0) / \Delta f$。
   - 若 $1\text{ LSB} = 50\text{ kHz}$ 由芯片内部硬件分频器写死，则 $c=280$ 对应 $76.0 + 280 \times 0.05 = 90.0\text{ MHz}$ 便是硬件计数器的物理天花板。强行改变软件比例只会破坏物理换算关系，导致全频段失调。
4. **步骤 4：器件手册与市场定位交叉印证**
   - 区分“芯片芯片组通用规格书（Silicon Capability）”与“特定终端设备硬件物料清单（BOM Implementation）”。
   - 调谐芯片（如 Sanyo LV24000/LV24020 系列）芯片本身虽覆盖世界频段（76–108MHz），但在 2004 年仅面向日本本土销售的随身听产品中，厂商为了在日本频段（76–90MHz）获得最高的信噪比与灵敏度，必然会选用更大感值的电感 $L$ 与高 Q 值的专用变容二极管，物理上彻底截断了 90MHz 以上的调谐可能。

**结论判定**：当四步证据全部闭环时，应当机立断停止无意义的软件暴力破解，接受硬件物理边界，产出最佳稳定版本收官。
