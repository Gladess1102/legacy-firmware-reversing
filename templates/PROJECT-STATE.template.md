# PROJECT-STATE — Single Source of Truth

> 用途：多 Agent / 多会话协作时唯一可信状态文件。每个会话结束前更新；每个会话开始时必读。
> 原则：**只记录"已确证"与"已否证"**，猜测必须标注 【推测】 并附验证路径。
> 实战来源：Sharp MP-B300 攻坚（26 版固件、三个异构 Agent 接力）。

## 1. 设备与目标（不变项）

- 硬件：SoC 型号、外围芯片（tuner/codec/电源）、存储布局、USB VID:PID（各模式）
- 用户的真实目标（按优先级排序，防止目标漂移）
- 硬红线（如"不能变砖"）与软偏好

## 2. 已确证事实（有实测/文件证据，禁止重复验证）

### 2.x 协议层
- 命令表：opcode / cmd id / CDB 布局 / 数据相方向与长度 / 返回语义 / 前置条件
- 每条注明证据来源：`【实测】` / `【SDK 文档 §N】` / `【反汇编 @addr】`

### 2.x 固件与文件
- 镜像布局（分区表、页大小、尾标规则）、已 dump 的分区清单与 md5
- 已解出的数据结构（资源记录格式、字模格式、消息号→语义）

### 2.x 机制模型（当前最佳解释）
- 现象 → 机制的因果链，附证据链
- 例：`断崖@90.0 = 读回值R(8bit,量程88.75) 经$B9EB重建4A15 → δ>8.2MHz 判失锁 → 静音`

## 3. 已否证清单（同样重要！防止换汤不换药）

| # | 假设 | 证伪实验 | 结果 | 版本 |
|---|---|---|---|---|
| F1 | 显式频段边界常量控制断崖 | 修改后真机听测 | 断崖不动 | v6/v8/v24 |
| F2 | ... | ... | ... | ... |

**规则：任何新假设提出前，先在 F 表确认没有前人踩过同一坑。**

## 4. 实验矩阵（版本号 → 改动 → 观测）

| 版本 | 基于 | 改动（字节级） | 观测 | 结论 |
|---|---|---|---|---|
| v24 | v10 | ... | ... | 日常版 |

## 5. 黄金基线

- 当前推荐日常版：文件名 + md5 + 刷写命令
- 紧急回滚链：`原厂dump → 基线 → 当前`
- 回滚命令（预设好，直接复制执行）

## 6. 剩余假设与下一步（按胜算排序）

每项附：验证成本（刷机次数/时间）、失败时的退路。

## 7. 教训登记（会话级事故复盘）

- 事故描述 → 根因 → 流程修正
- 例：NOP 硬件循环保护 → do a0 计数器下溢死循环 → 改跳转前必须识别 do/rep 上下文
