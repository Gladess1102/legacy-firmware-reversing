# Case Study: Sharp MP-B300（SigmaTel STMP3560 + DSP56004 + Sanyo LV24002）

> 2004 年日规硬盘 MP3 播放器。无官方源码、无公开刷机资料、厂商已消失。
> 本案例是本 Skill 全部方法论的实战来源；此处只留骨架，完整实验史见归档 PROJECT-STATE.md。

## 战役总览

| 阶段 | 战果 | 关键技术 |
|---|---|---|
| 协议逆向 | SCSI 厂商命令 C0/C1 全套（读页/写页/擦除/复位） | Group6 厂商命令 + SDK 文档 + BOT 短包陷阱修复 |
| 数据恢复 | 1GB NAND 全盘 dump、用户区 431MB 音库恢复 | `C0 13` 页读取、FAT 层重组 |
| 中文化 | 全机 280 条 UI 字符串 + 6,763 字 GB2312 全量字库，零尺寸膨胀 | 私有 GID 字典 + 槽位原位置换 |
| 机制建模 | 90MHz 断崖 = AFC 失锁判定 δ≈8.2MHz（读回值 4A15 值域不足） | DSP 指令级逆向 + JIT 仿真 + 全内存 Diff |
| 26 版证伪 | 显式边界/档位公式/CAP 直写/校验跳转/刻度 —— 全部真机否证 | 单变量二分法（16→8→4→2→1 处） |
| 终局裁决 | 判定逻辑的 handler 存在于**运行时 RAM 表**，固件镜像无静态实体；纯软件路线到底 | 消息调度器逆向 + 硬件通道（OnCE/TesterLoader）评估 |

## 给后来者的三个"如果早知道"

1. **BOT 短包终止**（支柱一）：一半的"设备挂起"是主机请求长度不整除 512B 造成的，不是设备坏了。
2. **运行时构造的代码**（支柱三）：当你把静态镜像翻个底朝天却找不到某判定的执行体，
   先怀疑它在 RAM 里被动态组装——用调度器逆向（找 `jmp (rX)` + 运行时表）确认，别再刷机盲试。
3. **硬件边界的体面收官**（支柱四）：四步判定法走完后，"交付最稳定的软件版本 + 写清楚硬件路线图"
   就是完整胜利。本案例最终交付 v24（全中文 + 76-90MHz 完好），归档于
   `夏普B300曲库备份/MP-B300破解归档/`（外置盘）。

## 复现要点

- 设备 USB：正常 `04DD:90C8`（SHARP MSC）；recovery `066F:3500`（Sigmatel Player Recovery）
- Flash 布局：target 05=bootmanager / 06=主系统 / 07=usbmsc / 08=资源+UI+字库 / 09=stmpsys
- t08 资源：24-bit **小端**描述符流（t05/t06 为大端——同一台设备两种端序！）
- tuner：Sanyo LV24002，3-wire GPIO（DATA=x:$F401 b19 / CE=x:$F403 b19 / CLK=x:$F411 b9 / NRW=x:$F421 b3）
